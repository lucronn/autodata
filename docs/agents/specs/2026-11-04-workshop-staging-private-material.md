## Descriptor-bound first-install manifest validation

The candidate runtime.validate_manifest performs `Path(__file__).parent / 'release.schema.json'` followed by Path.read_bytes, so a prior hash check of a different descriptor would not bind its actual schema read. Do not call it, do not globally monkeypatch pathlib, and do not expand the allowlist to change runtime-check.py. Define `validate_pinned_first_manifest(manifest, config, schema_bytes, runtime) -> str` only in private_material.py, with immutable descriptor-accepted schema_bytes. The selected candidate is the exact parity reference. In this order:

1. `config_hash = runtime.validate_config(config)`; `schema = runtime.strict_json(schema_bytes)`; `runtime._schema_validate(manifest, schema)`.
2. Require canonical manifest length <=runtime.MAX_JSON_BYTES and `manifest['service_config_sha256'] == config_hash`; call pure `runtime._validate_immutable_images(manifest, config)`.
3. Require migration count <=999; names sorted; numeric three-digit prefixes exactly 1..count; inventory_sha256 equals runtime.sha256(files).
4. Require manifest source equals selected CLI SHA, platform remains linux/amd64 by pinned schema, and rollback_source_sha is null. No rollback manifest/path is accepted by this first-install boundary.
5. Return runtime.sha256(manifest); require equality with approval canonical hash and descriptor-accepted raw manifest hash separately.

These pure functions have no schema pathname read, network operation or subprocess. Recheck all accepted descriptors and directory identities after validation and at commit boundaries. Their copies remain pinned in memory; a pathname substitution cannot select other bytes. Tests must replace the schema pathname after descriptor acquisition, make runtime.Path.read_bytes raise if called, and show either descriptor-identity rejection or use of only accepted schema bytes followed by rejection at final recheck. The deployment helper must not invoke a runtime function that reopens config/manifest/schema inputs by pathname. Tests compare this subset with the original candidate validator on accepted first-install fixtures and mutations, while the original validator's schema read is supplied only its exact candidate fixture bytes in the test harness. No validation branch or rollback permissiveness may be omitted except the explicit null-rollback restriction. This small duplicate pure sequence is intentional; a future shared-validator refactor would need its own allowlist/gate.

## Transaction and safety boundary

This helper is first installation on an accepted pre-daemon staging host only. It is not safe rotation on a running host. Before reading secret stdin or creating service material require root effective UID, trusted non-group/other-writable parents, fixed root-private subtrees, `/opt/autodata/current` absent, selected final service directory absent, no prior temporary tree/authorization journal, and both `/run/docker.sock` and `/var/run/docker.sock` absent. Resolve the normal root-controlled /var/run alias only for this socket absence observation; all material/approval/release traversal uses no-follow pinned dirfds. Socket absence alone is not quiescence proof: the concrete root-owned acceptance record defined above must positively attest no installed/running/restartable workload and no untrusted process with UID1000, bound to this authorization, machine and boot. This is a live-use prerequisite and limitation. A host with a Docker daemon already running or installed application lifecycle must use a later quiescence/rotation gate. This code does not stop a daemon, kill a process, claim quiescence from an assertion, or make maintenance effective.

Validate `/var/lib/autodata` as the exact mountpoint/approved UUID (ext4/xfs), and `/run/autodata` as the exact tmpfs with required flags, before mkdir/journal/lock. No ancestor-filesystem success, mount/format/chown of the mount root, boot-disk state, or mount creation. Pin mount root descriptors and stat identities. Recheck live findmnt observations, pinned descriptor/path identity and trusted binaries around every commit boundary. Use host_install's fixed findmnt probe, timeout requests and process-group kill/reap attempts. Preserve their existing code behavior without claiming a kernel-independent process-termination bound.

Acquire the existing fixed shared `/run/autodata/state/operation.lock` with nonblocking flock and exact root0600/regular/no-follow/single-link identity. If state does not exist, create only after valid mounts, as root0700. Revalidate lock inode/path identity before promotion; never unlink a lock file. All successor lifecycle helpers must use the same lock. Use one monotonic cooperative budget: stop initiating forward work at 270 seconds and reserve the next 30 seconds for best-effort cleanup/diagnostics. Never reset the budget per file/probe. Check remaining time before and after every blocking syscall, probe and journal boundary. Pipe/select/probe waits receive the remaining userspace timeout, but regular-file I/O, fsync, close, rename and kernel process waits can stall beyond that budget. This code slice makes no 300-second hard wall-clock or guaranteed cleanup/reap claim. A kernel stall may leave the helper and its flock held indefinitely; the durable non-success intent remains the only reliable interruption evidence. A later separately accepted supervisor and host recovery gate must address hung I/O before real use. The shared host_install Deadline may supply end/check behavior, but these checks cannot turn synchronous syscalls into cancellable operations.

Build `/run/autodata/.private-<authorization-id>` exclusively as root0700. Files begin root0600/O_EXCL/O_NOFOLLOW. Fully validate every input, write bounded bytes, fsync/close, chown final files1000:1000 and chmod0400; validate exact inventory, regular/single-link identity and bytes while descriptors remain pinned. Chown/chmod directory1000:1000 mode0500 only at finalization and fsync it. Recheck all trusted inputs, mount/device/lock/current/socket/target observations, and approval expiry, then no-replace rename the entire tree to the selected service. fsync tmpfs root, reopen and validate exact final inventory/metadata/bytes, close secret FDs, then finalize/fsync the durable non-success journal. Check the cooperative budget again after all blocking calls return before generating the final stdout operation receipt. If inode/path/mount trust changes, do not follow substituted paths or perform speculative cleanup. Cleanup only the transaction's exclusively created, identity-pinned tree; never remove an existing final directory. Mark incomplete/exit6 if safe cleanup or journal finalization cannot be established. SIGKILL/power loss cannot promise a final failure receipt; durable intent ensures absence of a passing record, and reboot destroys the tmpfs material.

Reboot tests here prove only that the helper does not create persistence, units, restart commands, current selection, or boot hooks, and that missing tmpfs/missing files deny the local helper. Actual lost-tmpfs writer restart protection remains an unresolved host-preparation/lifecycle successor, not a claim of this slice.
