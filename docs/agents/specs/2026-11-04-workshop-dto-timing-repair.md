Only the parent publishes the initial nonpass snapshot. Worker creation requires verified current-attempt initialization ACK and remaining schedule headroom. On blocked/failed initialization revoke the attempt, never start a worker, and return nonzero after bounded helper cleanup. If inventory or initial persistence never completed, report `initialization_unverified` and do not fabricate120 rows or claim an initial evidence file was written. A worker marker is a descriptor-backed internal protocol, not a user-supplied bypass flag; reject direct worker-mode requests without that owned descriptor. Never serialize secrets or full environment into evidence.

The parent owns the child identity from `Popen`, not arbitrary PID input. Python Popen itself has no creation timeout: do not pretend wrapping it with wait_for makes its syscall hard-bounded. The finite DTO-main claim is explicitly conditional on prompt monotonic-clock, process-create, poll, signal and bounded-size parent publication syscalls. Every parent filesystem read/write/parse other than the small publication critical section is isolated in helper processes. Parent-only final file operations have an additional explicit responsive-local-I/O assumption: each complete critical section (bounded metadata checks, descriptor-relative atomic rename/fsync and receipt publication) must finish within2s. Owned regular files alone do **not** prove this assumption. No finite guarantee is asserted for a parent blocked in the kernel or for Python interpreter/import startup; unconditional total-process lifetime and dead-parent revocation require the separately admitted independent watchdog. The bounded adapter interface and4440 schedule are conditional on these stated preconditions; any claim of unconditional supervisor survival under a stalled kernel/process-create/parent requires the separately admitted independent watchdog. Keep that runtime gate closed. All command/process calls are injected for tests. The parent uses the deadline established at the first main action, polls/awaits through bounded adapter operations, sends TERM only to its owned worker session at the hard worker deadline or external interruption, then KILL after2s, then bounded reap2s. Never use unbounded wait(), wait_for() cancellation drain, `asyncio.run()` worker completion, or join() in the parent. Group signaling covers the owned session only; actual browser descendant containment is **not** self-certified by these APIs. ## Evidence persistence and all-fail behavior

The evidence target is an atomic replacement in the fresh owned output directory, mode0700/file0600. Worker writes a separate progress file; parent owns final evidence.json. Persist after each case and lifecycle transition. The10s worker persistence allowance is cumulative across all its progress writes, not10s for each case. Charge serialization/write/acknowledgement against the same remaining allowance; exhaustion fails the attempt. Parent progress reads and JSON/schema/hash validation occur only in one isolated reader/parser helper at a time, limited to32MiB and10s **cumulative** across the worker interval. Its ACK is returned through a nonblocking size-capped control channel; the watchdog loop never performs file reads, JSON parse, blocking pipe reads or joins. Helper exhaustion revokes the attempt and triggers worker stop while helper stop/reap consumes the reserved cleanup budget. Progress cannot extend or mask the worker deadline. Reject oversize while retaining the raw file in place and without truncating diagnostics or trace bytes. Parent validates exact candidate/input pins, unique IDs, status values and final completeness before accepting progress. Reject malformed/truncated/stale/duplicate progress rather than promoting it. Record producer phase, failure kind, configured budgets, partial case observations and cleanup status without secret fields.

On case failure retain its original request/error/trace diagnostics. On global launch/start/stop/persistence/watchdog/cancellation failure produce **all expected IDs as failed**, preserve previously completed observations in `observed_case_result`, and never overwrite their original failure diagnostics. For unstarted IDs use `failure_kind=not_started_after_lifecycle_failure` with no invented requests/elapsed observations. `observed_case_result.status=passed` is historical observation only; terminal row remains failed. A successful normal run requires all120 current results passed, no global error, no unresolved task/resource and successful persistence/cleanup. No skipped/unavailable/missing row can pass. Filesystem failure keeps nonzero status and an explicit persistence failure; if writing is physically impossible, do not claim durable evidence exists.

Revision2 publication protocol (F1): helpers **stage bytes only**. A writer receives an exclusive `staging/<attempt_id>/<epoch>/<stage_nonce>.json` descriptor/path and may write/fsync only that staging artifact. No helper receives evidence.json or commit.json as a publication target; no helper API performs canonical rename. This is a source protocol for owned nonmalicious helper code, not a claim of host-level capability isolation. Staged success bytes are explicitly uncommitted observations and are never accepted on their own.

The parent maintains an immutable attempt_id (fresh128-bit identity, exclusive directory; existing attempt reuse rejected), monotonic epoch and terminal state machine `INITIALIZING -> ACTIVE -> PREPARED -> COMMITTED` or `INITIALIZING|ACTIVE|PREPARED -> REVOKED`. COMMITTED and REVOKED are terminal, mutually exclusive. Timeout, cancellation, lost ACK, uncertain helper exit or deadline exhaustion synchronously set sticky failure and transition to REVOKED with epoch increment **before** cleanup signals. Late ACKs include attempt_id/epoch/stage_nonce/content_sha256/byte_length and are ignored unless they exactly match the active request and parent state; late stage files can never change terminal state. No signal send, TERM/KILL success or timeout is treated as write revocation. Revocation is the parent's loss of commit eligibility; no helper ever possessed publication eligibility.

Publication proceeds only after the worker exited successfully and was reaped, every helper was acknowledged and reaped, current progress has all120 passing IDs, cleanup is confirmed in the code model and final-stage ACK matches. The parent drains pending cancellation/deadline events, checks `now < producer_deadline -2`, checks ACTIVE/PREPARED state+epoch+attempt and matching final content hash, then performs the one serialized parent-only commit critical section. No await or helper action occurs between that fence check and publication; cancellation handlers only latch events, which are checked before entering. The critical section atomically publishes evidence.json and a separate commit.json receipt; the receipt is published **last** and includes version, attempt_id, epoch, candidate_sha, timing_contract_sha256, evidence_sha256, terminal_state=committed and cleanup_status=verified. Evidence includes the same attempt/epoch plus publication_state=requires_commit_receipt; bare status=passed is never an authority. Only a full receipt ACK before the deadline changes the parent's state to COMMITTED and allows exit0. A failure/timeout/cancellation before that ACK revokes, returns nonzero and never schedules another success commit.

Success consumption rule is conjunctive: exact same-attempt invocation exited0; parent terminal receipt matches a fresh expected attempt_id, current epoch, candidate/input pins and evidence digest; all120 IDs passed; cleanup status verified; no known revocation. Missing, uncommitted, old-attempt or ambiguous receipt is nonpass. `commit_uncertain` covers interruption during atomic rename/fsync/receipt publication or a syscall exceeding the responsive-I/O assumption: return nonzero, retain raw stage/receipt bytes, never infer success, and never pretend those files are revoked merely by signals. A receipt without same-attempt successful invocation acknowledgement is insufficient. Existing consumers that do not enforce this rule are **not admitted** by this task; release assembler stays gated and unmodified. Parent crash after receipt publication but before exit0 remains nonpass/unverified for this attempt. COMMITTED means a fully acknowledged terminal decision, not a promise that no future unrelated caller can overwrite paths.

Writer/reader helpers have bounded shutdown: per helper TERM2s +KILL2s +reap2s, at most two cleanup episodes after the first global fault, total12s. The first failed helper ends new work admission; only one final **nonpass** staging attempt may follow, and its failure ends all helper creation. Final-stage read/parse/write has10s shared; final parent commit has2s; these are included in4430, not added after4440. Helpers not confirmed reaped are recorded cleanup_unverified and prohibit success even if staging ACK arrives later. A failure may leave the last verified nonpass snapshot or physically absent evidence; neither is relabeled durable complete evidence. Existing trace files remain byte-preserved with the current16MiB policy; assembler8MiB admission remains blocked.
