## 3. Interfaces and supported states

`policy.py` defines frozen `Limits`, `Contract`, `CommandSpec`, `FileSpec`, `Identity`, `Problem`, `SafeObservation` and `Receipt` dataclasses. Untrusted inputs enter through `admit_contract(document: bytes) -> Contract | Problem`, `parse_bounded_json(chunks, budget) -> JsonValue | Problem`, and per-kind `project(kind, value, contract) -> SafeObservation | Problem`. All errors use fixed enum codes and approved identifiers; neither exception text nor arbitrary input values enter results.

`collector.py` exposes `collect(contract, files, commands, outputs, clock, cancel) -> CollectionResult`. Each injected port is explicit, with no default instance:

- `FilePort`: begin an approved descriptor-relative open/absence/metadata check; deliver bounded identity and byte events; revalidate the same descriptor/entry. There is no arbitrary path API, directory walking, glob or discovery method.
- `CommandPort`: start one exact `CommandSpec`; deliver stdout/stderr byte events, exit/EOF events, identity rechecks and termination acknowledgments. There is no arbitrary argv/shell execution API. Every spec is admitted before port invocation.
- `OutputPort`: exclusive create/write/flush/fsync/identity events for exact approved output names only. It cannot overwrite, reopen, rename, unlink or choose a fallback filename.
- `Clock`: integer monotonic ticks supplied by the caller; reject backward time. `CancelPort`: cancellation predicate/event, checked at every boundary.

Ports are protocols and scripted fakes only in this increment. Importing modules constructs no ports, reads no environment, launches no thread/process, installs no signal handler and performs no I/O. No `subprocess`, socket client, Docker SDK, OS observation adapter or `__main__` path exists. Production adapters must later prove they implement real descriptor-relative no-follow and enforceable deadlines; this design's fake identities are not such a proof.

State transitions are `NEW -> ADMITTED -> FILE_ELIGIBLE -> COMMAND_ELIGIBLE -> PROJECTED -> COMPLETE` with terminal `BLOCKED` or `INCOMPLETE`. Prerequisites are per observation: no Git command before config eligibility, no Compose before clone/Git/source eligibility, no effective model before a complete approved baseline. Missing approved clone/config may allow independently authorized nondependent observations; no failures trigger retries, repairs, cleanup or expanded scope. A cap/deadline/cancel/storage/identity breach stops the entire attempt immediately.

## 5. Nonrenewable budgets and real-adapter obligations

Copy these exact limits from the reviewed draft; smaller remaining cumulative/outer budget always wins:

| Resource | Bound |
| --- | --- |
| Approved regular inputs / total metadata entries | 20,000 / 40,000 including parents and absence checks |
| Input file / aggregate input / chunk | 64 MiB / 1 GiB / 64 KiB |
| Each file or absence check / cumulative file+metadata | 5 seconds / 300 seconds |
| Each derived JSON/model/receipt/output | 16 MiB |
| JSON values / nesting / UTF-8 string / collection members | 1,000,000 / 64 / 1 MiB / 20,000 per array/object |
| Parse, validate, serialize | 5 seconds each operation per document; 60 seconds shared aggregate |
| Each write/flush/fsync / all output operations | 5 seconds / 60 seconds |
| Command stdout+stderr / aggregate command capture | 16 MiB / 128 MiB |
| Persisted output aggregate | 128 MiB across 17 exact names |
| Ordinary / source-related command deadlines | 10 seconds / 30 seconds as specified per command |
| Outer attempt / free-space floor | 30 minutes / 1 GiB before every command and write |
| Own observation child/group termination | 2 seconds TERM, then 2 seconds KILL; never daemon/other process |

Charge bytes before appending/decoding; every chunk is checked against all remaining bounds. Include both stderr and stdout even if stdout alone parses. Limits and clocks never reset between phases or commands. The free-space floor is a prerequisite check, not a claim of reservation; write/ENOSPC errors remain terminal. No response after a breach can become accepted complete evidence. Use a bounded incremental UTF-8 JSON tokenizer/parser; checking depth after a stock unrestricted parse is insufficient. Enforce member/node/string limits before accepting/allocating the next token/value, reject duplicate keys at every depth, malformed UTF-8, nonfinite numbers, trailing data and unsupported numeric forms. Serialize only closed-schema output with size/time charging; never serialize an untrusted object as a diagnostic.

Real adapter obligations for a later gate: anchor owner-approved directory descriptors; open parents with O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC, leaves O_RDONLY|O_NOFOLLOW|O_CLOEXEC; reject symlinks, special files, untrusted writable parents and unapproved mount/device changes. Compare dev/inode/type/uid/gid/mode/size/mtime_ns/ctime_ns to approved identity after open, before/after hashing the same descriptor, and revalidate directory-entry identity. Parse the bytes from that descriptor; never reopen after hashing. Absence accepts ENOENT only with validated parent and before/after dependent-operation rechecks. Socket checks are metadata-only. Outputs are descriptor-relative O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC mode 0600, root/subdirectories 0700, umask 077; require expected ownership/device/link count/parent and final identity.

A synchronous blocking open/read/fsync cannot be made bounded merely by checking the clock afterward. A production adapter must provide independently reviewed cancellation/isolation primitives and bounded IPC, including behavior for blocked kernel I/O, unavailable no-follow primitives and an uninterruptible child. No such adapter is implemented or claimed here. If actual bounds cannot be enforced, real collection stays blocked. Cancellation is not permission to kill unrelated processes or clean Docker resources.

## 6. Privacy, outputs and compatibility projections

Raw command/file content stays bounded and transient in memory. No stream files, debug dumps, command error text, exception repr, crash attachment or arbitrary JSON passthrough. Hash complete stdout/stderr separately only after EOF; prefix digests on interrupted streams carry `complete:false` and cannot satisfy a complete-output digest predicate. Hashing withheld data is permitted by the reviewed policy but does not make the data eligible for persistence. Python cannot promise secure memory zeroization; this design promises no deliberate raw persistence, not forensic memory erasure. Core dumps/swap/storage controls require the later owner-controlled runtime contract; absent required controls block dispatch.

Project version strings to validated product/version fields capped at 512 characters. Daemon info must have empty proxies, linux and raw architecture exactly amd64 or x86_64, preserving the safe raw string and normalized amd64; image architecture remains exactly amd64. Persist hashed daemon identity only. Any private raw identity record requires separately explicit approval within the existing output schema; there is no extra output filename.

For each of the four exact image IDs in the specification, require one complete inspect object, exact ID, linux/amd64, Config/RootFS/RepoDigests and stable identity. Preserve only approved safe stable fields plus Config hash. Runner Config.Env accepts only PATH/HOME/LANG/LC_ALL/TZ/SSL_CERT_FILE/SSL_CERT_DIR, with no duplicate/invalid paths; PYTHON_VERSION/PYTHON_SHA256 and every extra key, including empty values, block. Persist rejected-key diagnostics as the fixed code `unapproved_key` and an integer count only; do not copy or hash any arbitrary rejected name. The only optional rejected-key text is a name selected by exact equality from the literal owner-approved set {PYTHON_VERSION, PYTHON_SHA256}; this set cannot be expanded from input. Apply the same closed-literal projection to arbitrary JSON object keys, input-derived error identifiers and path labels: syntax validation alone never makes their text safe to persist. Never persist rejected values. Full Config persistence requires a literal owner-approved closed nonsecret schema. A hash cannot replace full Config required by later launcher admission. Owner approval of the complete base and merged interpreter env maps remains a future requirement.

Inventory stores counts, complete digests and booleans for exact planned names/owner/project labels only; no unrelated names/IDs. Compose baseline/effective documents are accepted whole only after every string/value matches the approved candidate-derived literal model and exact root/token substitutions. Withhold the entire model/receipt on any unapproved value; redaction cannot yield complete-model evidence. Apply only the frozen transformation: remove test-runner, use four pinned images and pull_policy never, remove runner build, replace the entire minio volumes list with the sole approved run-root bind. Require exact service set postgres/nats/minio/go-test-runner, no build, and whole-model equality after effective Compose resolution. effective.json is inert derived data; it never grants execution authority.

The output-name set is exactly: owner-contract.json, dispatch.json, command-manifest.json, source-pins.json, file-observations.json, tool-observations.json, daemon-observations.json, image-observations.json, inventory-observations.json, compose-baseline.json, effective.json, compose-effective.json, command-receipts.json, classification.json, REPORT.md, SHA256SUMS, independent-review.md. The fake output port exercises these names in memory. No real file is produced by tests. In production the operator/reviewer may precreate their own names once; the collector must not overwrite them or forge independent-review.md. Output ownership is explicit in the dispatch, and an unapproved existing name blocks. Each aggregate is written once, not updated in place. An independent review is never manufactured by collector code.

Finalization has this exact order: (1) finalize, fsync and validate identity for every present required non-report payload, including owner-supplied contract/dispatch files; (2) exclusively write, fsync and validate REPORT.md, which lists every present payload and every withheld/absent allowed name with a fixed reason code, records its classification, and states `completion_requires_validated_SHA256SUMS_and_final_receipt`; (3) exclusively write, fsync and validate SHA256SUMS, containing lexicographically sorted SHA256 entries for every finalized present file from steps 1 and 2, including REPORT.md, excluding only SHA256SUMS itself and the later reviewer-owned independent-review.md; (4) only after checksum finalization succeeds, return the final in-memory completion receipt containing the SHA256SUMS digest, exact covered-name set, attempt/checkpoint binding and `collection_status:complete`. There is no extra receipt file. No report is labelled COMPLETE: REPORT.md alone cannot establish completion. SHA256SUMS may exclude withheld/absent files only when REPORT.md names their absence; omission of any present finalized payload or REPORT.md invalidates the manifest. No file is modified after hashing. The independent reviewer later binds the finalized manifest digest, receipt and reviewer-owned independent-review.md in its external review record; collector code does not emit that attestation. Missing, lost or invalid final receipt means incomplete until independently validated recovery under a separate contract; no automatic recovery occurs.

## 7. Failure precedence and report meaning

Precedence for the primary attempt outcome is: (1) missing/invalid authority or unresolved admission prerequisite, before any affected I/O; (2) cancellation, time/cap/storage breach or integrity/race failure, which stops all work and produces incomplete evidence if safe reporting remains possible; (3) incomplete/nonzero/malformed/unsafe command or projection result; (4) fully evidenced source incompatibility; (5) missing compatibility input; (6) preparation compatibility. Preserve every safe blocker reason even when a higher-precedence outcome wins. For concurrent stop events, select a stable enum ordering cancel, deadline, cap, storage, integrity; never allow a success event to overwrite a stop latch.

Malformed/truncated/withheld output is not a source counterexample. Per-blocker classification is only compatible, blocked_missing_input, or source_incompatible; use source_incompatible only with complete trusted observation and safe exact source-field counterexample. Incomplete attempt is a separate top-level collection status; it cannot declare preparation complete. A fully completed report remains preparation_complete_execution_blocked unless all preparation predicates pass, in which case preparation_compatible_pending_execution_gate is the maximum result. Full created-container HostConfig/mount/network shape cannot be established from version/help/image inspect; absent authorized provenance-bound saved shape evidence remains blocked_missing_input. No discovery container is created.

On failure, stop scheduling, terminate only the one owned observation child/group, and await the bounded acknowledgments. No automatic retry, file removal, Docker cleanup or repair. If any payload, report or checksum write/fsync/identity validation fails, return an in-memory fixed incomplete result to the coordinator; leave private partial output as incomplete. Follow the exact finalization ordering above, with REPORT.md preceding SHA256SUMS and the successful in-memory receipt last. A report classification or valid-looking checksum never overrides a failed or missing finalization step. Process loss without a final receipt is incomplete, even if some files look valid.
