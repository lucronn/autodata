## Backup helper

Public interface remains `backup-host.sh begin|status|export|resume <uuid>`. Parse exactly two arguments; require canonical lowercase UUID v4, reject unknown verbs and inherited environment. The wrapper executes `/usr/bin/python3 -I` with an empty environment, loads only `/opt/autodata/bin/backup_restore.py`, changes cwd to `/`, and accepts no caller paths, shell or credentials. Root uses installed current release/config, disk UUID, metadata/storage guard, exact nine-service graph, cached images, migration inventory and tmpfs secrets from the existing runtime and host-activation validation primitives.

Use both existing operation locks in the existing order: `/run/autodata/state/operation.lock`, then `/var/lib/autodata/operations/activation.lock`. They serialize all local mutations including watchdog, private material and activation. Do not invoke a separately locking deploy CLI while holding them. Read/recheck pinned descriptors; reject symlinks, hardlinks, wrong owner/mode, changed ancestors and foreign service/container identities. Backup lease directories are root-owned0700 under `/var/lib/autodata/operations/backups/<uuid>`; files0600 and atomic fsync/replace. UUID directories are never reused for a new attempt.

Before mutation persist lease intent: UUID, boot ID, selected source SHA, canonical release manifest hash, expected disk UUID, started UTC, monotonic deadline, UTC expiry, current phase and incomplete flag. Lease is exactly1800seconds, with300seconds reserved for recovery; record intent before every mutating step. Enter verified Caddy maintenance503, stop all five writers (`api`, `ingestion-http`, `article-worker`, `payment-reconciler`, `outbox-relay`), validate they stopped, produce custom-format PostgreSQL dump while PG is running, verify it with `pg_restore --list`, hash it, then stop `postgres`, `nats`, `minio` and sync the mounted data filesystem. `begin` succeeds only after rechecking the exact stopped state. Keep Caddy up in maintenance. No snapshot or upload command exists locally.

`begin` timeout is600seconds; total lease1800seconds; every child has a finite timeout/output bound. Stream dump to an exclusive descriptor; never buffer an unbounded database in RAM. Dump and export caps follow existing `cloud-ops.py` MAX_EXPORT=1073741824; JSON/receipt cap65536. Reject dump>=MAX_EXPORT, insufficient free space, and archives exceeding MAX_EXPORT. Do not expose SQL rows or stderr. Snapshot timing is wholly external; a local quiesced receipt alone certifies no snapshot.

`resume` is idempotent for the same run and release. Recheck mount/guards/secrets/images/selected release before starting stateful services, then applications in the existing host startup order; require actual no-work readiness before removing maintenance. Resume timeout300seconds. Recovery failure leaves maintenance, marks incomplete and returns6. Secrets missing after reboot must leave apps stopped. Interrupted begin makes a best-effort bounded safe resume in a finally path and keeps the run incomplete. Never hide the primary failure after a successful recovery.

The watchdog is a root-only local Python entrypoint with no caller-controlled argv: `backup_restore.py watchdog`. Timer interval30seconds; service timeout330seconds; no Google identity, network credential or arbitrary command. The service runs after the expected mount/guard prerequisites. Watchdog scans at most100 run directories, rejects malformed state and concurrent lock ownership, and attempts recovery for expired/abandoned leases; stale boot ID means incomplete and recovery guards still apply. An automatic recovery never changes incomplete to complete and invalidates external snapshot success. Unit files are tested as inert definitions only in this leaf.

`status` is read-only and cannot invent a success. Successful begin uses state `quiesced`; successful resume/status state `resumed`, with exact COMMON_RECEIPT/BACKUP_FIELDS consumed by `cloud-ops.py:_host`, including dump size/hash, manifest hash, disk UUID and expiry. `writers_resumed` and `stateful_resumed` are true only after measured recovery. Checks are existing runtime CHECK_NAMES. Failure receipts preserve failure/incomplete state; no secret/customer identifiers appear. Exit0 success,2 invalid input,3 missing prerequisite,4 operation failure,5 timeout,6 incomplete recovery.

`export` is allowed only after successful explicit resume, for that UUID and pinned release. Stdout is only bounded regular USTAR with exactly `postgres.dump`, canonical `release.json`, and `backup.json` equal to a fresh successful status receipt; stderr is generic failure only. No `/run`, secret, database path, extra file, link, PAX/GNU extension, traversal or duplicate entry. Verify the final stream with existing `cloud-ops.py:verify_export`; retain local dump until separate retention authority applies. Export does not upload or mark the snapshot verified. A failed stream remains a failed export even if some bytes reached the caller.

## Isolated restore helper

Public interface remains `restore.sh restore|validate <uuid>`, with the same wrapper/input/receipt rules. It never selects/releases production or writes production data. A separate root-owned0600 plan is fixed at `/etc/autodata/restore/<uuid>.json`; exact keys: `schema_version`(1), `run_id`, `source_sha`, `manifest_sha256`, `archive_sha256`, `expected_disk_uuid`, `restore_disk_uuid`, `postgres_image_id`, `fixture_inventory_sha256`. Values have strict scalar types and UUID/SHA formats. Restore UUID must differ from production data UUID; restored manifest source/hash must match supplied archive. No arbitrary target, command, URL or SQL field exists.

Inputs live under a separately mounted `/var/lib/autodata-restore/<uuid>/input` and output under `.../result`, both0700 and descriptor-pinned. Reject same device/UUID as `/var/lib/autodata`, missing independent mount, a pre-existing result, populated target, symlinks, path substitution, unexpected files, wrong ownership and any existing container/name. The input directory contains only `export.tar`, `inventory.json`, `cold-state/`; inventory is canonical hashed nonsecret expected evidence. Production `/opt/autodata/current` and production Compose project are never used to choose restore targets. No bind mount of live `/run/autodata` is allowed.

Restore parses raw bounded USTAR through the existing export verifier before writing dump bytes. Require PostgreSQL major17 and exact approved image ID. Create only UUID-labelled `autodata-restore-<uuid>` disposable containers/volumes on an internal Docker network with no published ports or host network; only fixed PostgreSQL/NATS/SeaweedFS test roles, no configured commerce/API/workers/reconciler. Never pull images. Credentials are synthetic per-run fixture values only in the local fixture; a future actual-data restore requires separate secret-delivery authority. Restore the dump using `pg_restore --exit-on-error --no-owner --no-privileges`; no live database host/connection string is accepted. Owner/privilege recovery is not claimed by this portable proof.

`validate` requires the same plan and exact owned created-resource inventory, verifies migration ledger equals released SQL inventory, exact synthetic ownership/session/order/grant/article rows, referenced source object bytes/hashes, and persisted JetStream message/consumer state from copied cold-state. Inventory explicitly lists expected relations/counts/hashes, object keys/hashes and JetStream stream/sequence/payload hashes; bounded inventory has at most1000 records and1MiB canonical bytes, each payload<=1MiB. Production schema uses the released migrations and fixture inserts; no invented simplified substitute schema qualifies. Orphaned relations, wrong owner, missing object, corrupt dump, missing message and mismatched ledger are failures. No provider fetch, payment replay or application startup is used.

Timeout for the entire disposable local proof is900seconds, including120seconds cleanup reserve. Local proof returns nonzero if dependencies/pins are unavailable, validation fails, any container OOMs, or cleanup cannot confirm all owned containers/networks/volumes removed. Evidence is external to deleted resource roots and contains exact source/image IDs, commands with synthetic secrets redacted, fixture/archive hashes, outcomes/durations and cleanup flags. Failure evidence remains retained. This proves portable database restoration and synthetic cold-state recovery only; real disk-snapshot restore, all production objects, actual accounts/provider observation, scale/RPO/RTO and end-to-end ingress recovery require the separately authorized staging drill.
