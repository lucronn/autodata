## Goal and existing contracts

Provide an executable staging-first path from the accepted bare GCE VM to an installed host runtime, accepted immutable image cache, and migrated initial database; reuse existing inert release install and maintenance-first activation.

The executable `staging_bootstrap.py` creates the VM, data disk and address; it does not install host packages or initialize its filesystem. `host_install.py` accepts only authenticated owner-accepted inert release/migration material. `private_material.py` delivers accepted private material. `host_activation.py` starts an already provisioned host with cached images and an already correct schema. None is replaced here. `runtime-check.py` supplies manifest/config/image/mount/guard/schema validators and `render_bundle`. `runtime-grants.sql` supplies metrics/relay grants. Existing relay changes are outside scope.

## Review correction verification

The reviewed candidate now rejects an existing target filesystem UUID using an uncached blkid scan both during preflight and immediately before mkfs. After mount it verifies the approved device major/minor alongside UUID/type/options; before chmod it checks the opened mount descriptor's actual device. Data directories are created relative to that pinned, device-verified descriptor, preventing boot-disk fallback if the mount pathname disappears.

A stopped Docker daemon is insufficient evidence of a fresh host. Preflight also rejects populated Docker/containerd persistent or runtime directories, preexisting daemon configuration, and systemd overrides that could redirect the state root. Immediately before Docker startup it rechecks default persistent/runtime state and socket absence, so the new helper cannot resurrect a previously stopped restart-policy container.

A resume's prior journal is hash-bound and statically checked for source, operation, incomplete status, PostgreSQL-creation stage, manifest/config/bundle/image-cache receipt bindings and an accepted leading migration prefix before lock-file creation, rendered-file materialization or PostgreSQL startup. Actual observed ledger-prefix comparison remains a separate subsequent check. Regressions exercise every static binding refusal before later private-input reads or mutation, UUID collision and wrong-device mount rejection before chmod, descriptor-bound temporary data-directory owners/modes, and persisted Docker/containerd refusal. These corrections do not replace the outstanding disposable Debian12/systemd/reboot probe.
