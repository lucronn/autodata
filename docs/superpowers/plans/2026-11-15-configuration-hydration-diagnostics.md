## Diagnostic event contract

Use existing module logger WARNING only for configuration hydration anomalies, so default production logging captures the signal without a logging/env/dependency change. Healthy providers, complete cache hits and deliberate deepening cancellation emit no new warnings. One fixed format: `catalog configuration diagnostic scope_hash=%s provider=%s stage=%s outcome=%s error_type=%s row_count=%d`. Never pass an exception object to logger args, stringify an exception, include traceback/exception_info, or interpolate untrusted strings/payloads.

- `scope_hash`: first16 lowercase hexadecimal characters of SHA256 over UTF8 compact sorted JSON containing exactly scope=configurations, year as a stripped decimal string, make/model stripped+casefolded, region stripped+uppercased. This internal correlation hash matches across foreground and background requests and reveals no raw selector values. No external request/vehicle/article/source identifier is logged. The diagnostic helper must not change hydration behavior or raise if given invalid request inputs; invalid external input continues through existing validation and status handling without a new diagnostic requirement.
- `provider`: only bankone, banktwo, unknown or aggregate. SourceCatalogProvider exposes/derives this from the configured client.provider through an explicit two-bank allowlist. Never inspect or log baseURL, tokens, source locators, provider payload labels or opaque refs. Aggregate means a merged persistence/configuration stage; it must not blame a bank.
- `stage`: fixed enum provider_configuration, provider_resolution, provider_projection, row_persistence or coverage_persistence.
- `outcome`: fixed enum unconfigured, failed, incomplete or not_persisted. It describes the stage result; it changes no complete/hydrating/HTTP result.
- `error_type`: none for nonexception anomalies; otherwise an explicit safe class-name allowlist {TimeoutError, ConnectionError, OSError, ValueError, TypeError, KeyError, SourceConnectorError, S3Error, OperationalError, InterfaceError, IntegrityError, ReadOnlySqlTransaction, InsufficientPrivilege, UndefinedTable, UndefinedColumn}; every unrecognized class becomes OtherError. No raw str/repr/args/code/status/requestbody. A dynamically named secret-bearing exception class is therefore also redacted.
- `row_count`: actual normalized-row count where available, otherwise -1 for unknown. Never log rows or raw missing-scopes entries.

This is anomaly telemetry, not proof a request started or that a bank succeeded. Positive completion remains the exact durable coverage/provenance read; warning absence must not be interpreted as success. Scope hashes permit the next separately authorized exact branch observation to distinguish its anomalies from existing background deepening.

## Minimal call-site design

1. In CacheFirstCatalogService.resolve, preserve the existing _call_provider exception flow: _SelectorDeepeningStopped rethrows without warning; other caught exceptions retain current missing-provider/continue behavior and add a bank-labelled provider_resolution/failed safe event only for configurations.
2. Wrap the already-existing normalization/merge/provenance/missing-scope projection block solely to log provider_projection/failed and rethrow unchanged if it raises. Do not move these exceptions into the continue path, change the partial-row merge, alter provider ordering or swallow new failures.
3. When the existing completion predicate for a configuration provider is false, emit provider_resolution/incomplete with normalized count and error_type=none. Preserve all-provider completion and missing-scope behavior byte-for-byte in outcome.
4. In ensure_catalog_hydration, log provider_configuration/unconfigured for the existing no-configured-clients configuration result. At internal row_persistence/coverage_persistence exceptions, use one aggregate safe diagnostic, including ValueError; rethrow unchanged with current HTTP handling. Configuration events replace its old unfiltered class-name warning to avoid duplicate/unsafe exception names. Invalid-request validation remains unchanged; makes/models/article logging is outside this implementation scope.
5. After configuration coverage persistence returns, if status is not persisted, emit aggregate coverage_persistence/not_persisted with the resolved-row count. Do not log raw status text or create a partial configurations marker. A complete empty provider enumeration may legitimately have no persistable rows and still write its complete marker; do not warn merely because its row count is zero.
