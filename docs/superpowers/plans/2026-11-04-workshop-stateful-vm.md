> **For agentic workers:** Planning-only draft. After a synchronized committed checkpoint, pinned preflight, independent exact-checkpoint review and fresh coordinator dispatch, use superpowers:executing-plans task-by-task. This plan does not dispatch agents or authorize VM/Docker operations.

**Goal:** Implement transactional local installation and PostgreSQL/NATS/SeaweedFS boot, persistence and interruption/reboot recovery in a disposable offline VM while preserving every application, cloud staging and production execution boundary.

**Architecture:** Add a separate fixed-path lab helper and stateful-only Compose profile. Consume independently approved pre-provisioned VM/disk/tool/cache identities, privately delivered synthetic credentials, fixed probes and bounded operation receipts. **Tech Stack:** Python 3.12+ standard library, Linux x86_64 KVM guest, Docker Engine/Compose with explicit approved binary hashes, PostgreSQL17, NATS JetStream and the repository-pinned SeaweedFS image; no new Python/Node dependency.

**Spec:** `docs/superpowers/specs/2026-11-04-workshop-stateful-vm-design.md`.

## Transaction, lock and fixed state

Pin parents/files with dir_fd/O_NOFOLLOW/O_NONBLOCK and pre/post inode/owner/mode/size/mtime/ctime checks; no links/devices/FIFO/socket or traversal, and nlink1 for ordinary files. Standard parents root:root0755 are valid; private lab roots0700 required. Verify mount observations and pinned directory st_dev/inode before every persistent phase commit, including receipts. Missing mount fails before mkdir/data-file creation; no boot-disk fallback or mkdir-through-symlink. Mount identity observation does not establish GCE disk identity.

Acquire exclusive nonblocking flock `/run/autodata-lab/state/operation.lock`0600 for the whole operation after verified tmpfs; same exact lock for every verb, busy exit3. Root directory creation is limited to approved existing data/tmpfs/release parents. All receipt/status operations are atomic temp file + fsync + same-directory rename + directory fsync. Pending operation record is persisted before Docker mutation. Record exact observed Docker IDs and phase after each step; labels alone never establish ownership. Locks are process lifetime, not PID text; revalidate approval before every mutation.

Install: require bare run (no containers), validate entire source before copy, exclusive `.install-<authorization_id>` under release root, copy/hash/fsync complete bundle0444 with dirs0500, re-read all bytes/mount identities, promote via renameat2(RENAME_NOREPLACE), fsync parent. Existing final tree passes only exact inventory/bytes/owner/mode equality; mismatch never overwritten. Stale temporary tree yields incomplete recovery for operator inspection; never recursively delete an unowned tree. In-process failure removes only exclusively created identity-pinned files/dirs; cleanup failure is exit6. No `current` symlink or production release object is created.

Installed nonsecret run profile `/var/lib/autodata-lab/runs/<RUN_UUID>/compose.json` and `state.json`0600 bind source, approval content identity, VM/mount/profile/image digests, current boot ID and exact observed resources. On reboot approval_id/boot_id/expiry may change only after coordinator approval; every other run/VM/data/source/helper/image/profile binding remains identical. Old expired approval cannot start/recover. Run state records phase, not a success certificate; always recollect services/probes.
