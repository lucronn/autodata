## Problem and concrete decision

A public configuration list can schedule background ensure even when usable rows exist and its marker is absent. Go clones context.Background(); its HTTP timeout does not cancel the Python traversal. Direct ensure currently supplies no control to providers, permitting1000 outer pages per bank plus nested Banktwo parent-label pagination/repair. Existing selector-deepening control applies only makes/models background walks. One public GET is not proof of bounded upstream fanout.

Add a distinct configuration-only control:12 total HTTP/page-attempt reservations and20s monotonic deadline shared by ALL configured banks for one ensure, including initial catalog pages, every outer cursor page, Banktwo parent makes/models pages and repaired retry. Reuse existing provider timeout/before_additional_request/deadline propagation into SourceConnectorClient; no source-client transport rewrite or provider endpoint bypass. One request consumes one slot immediately before its dispatch; exact12th request may complete successfully, a13th cannot dispatch. Check elapsed/cancellation before each dispatch and after each response, plus before row/coverage persistence. Unlike selector deepening, no six-second global floor or _DEEPEN_NEXT_DISPATCH mutation; connector services retain their shared limiter. A429 stops the configuration job without retry/next-bank storm. Genuine upstream errors while budget remains retain existing semantics; if a SourceConnectorError wraps elapsed deadline, check control.remaining first so expiry is local cancellation rather than supplier failure.

Use a distinct local stop sentinel (a selector-stop subtype for existing resolver propagation) with allowlisted reason request_limit/elapsed/cancelled/rate_limited. Local stop propagates through resolver and current HTTP502 path; it must not persist a false complete marker, be cached as complete, or be logged as provider_resolution/failed supplier failure. No guarantee of newly fetched partial-row persistence on stop is claimed; existing cached rows remain available. Unfinished work stays partial. Existing all-bank completeness, persistence, marker/flag authority and normal upstream error behavior remain intact.

Emit safe fixed-field configuration budget start/finish events: scope hash, random per-attempt token, state started/finished, stop reason enum, attempted count0..12 and elapsed milliseconds. No selectors/URLs/credentials/payloads/exception text. A finished execution event is not a completeness claim. Existing configuration diagnostic must identify the allowlisted local stop type/outcome incomplete. Finally emits matching finish event after provider calls/persistence have returned or raised; no late callback/future is introduced. This permits a future watchdog to correlate actual job termination. Logging failures never alter hydration behavior.
